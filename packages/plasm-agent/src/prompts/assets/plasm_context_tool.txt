**Returns a language card** with a session symbol table, selected business capabilities, declared prerequisites and input bindings. Call before `plasm` / `plasm_run`; this tool performs no acquisition or business calls.

**Intent-only lifecycle:**
- `session_mode: "new"` + `intent`: describe every business requirement. Ready creates `logical_session_ref` and fresh symbols. Use once per workflow.
- `session_mode: "extend"` + the same `logical_session_ref` + current `intent`: select against the pinned generation and exposed capabilities. Existing symbols and bindings remain unchanged; teaching appends the admitted delta.
- `intent` does NOT select the session. Repair plan or parse errors with the same ref.

**Routing outcomes:** `ready` reports that the presented capabilities support the requested workflow. `insufficient` reports missing functionality within the presented set and can accompany useful teaching. Preserve useful capabilities and use intent-only extension when more are needed. You own conversation and execution: ask the user when needed, then write only the chosen program. Neither status authorizes execution or guarantees success. Routing errors are operational failures. Empty additions on extension preserve existing capabilities and bindings.

Infrastructure dependencies come from declarations. Write the taught provider calls as ordinary Plasm programs and bind their outputs into the specified existing inputs. Submit programs to `plasm` for review and execute returned `run_ref` plans with `plasm_run`.
