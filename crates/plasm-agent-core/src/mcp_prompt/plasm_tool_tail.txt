Prefer **one `program` per call**: use **newlines** for bindings (`ident = …`), then **comma-separated roots** on the final line when returning multiple surfaces (e.g. `sorted, count`). Bracket-render yields **`binding.content`** for string slots. Postfix (`.filter{…}` / `.filter(…)`, `.limit`, `.sort`, `.aggregate`, `.group_by`, `[…]`, `[fields] <<TAG…TAG`) chains when legal.

**Brace `{…}` predicates:** entity-ref slots accept the **same surfaces as gets** — inline `eN(p#=…, …)` compound ctor, wire `Entity(k=v, …)`, label ref from a prior binding (`repo`), or `anchor.<relation>`. Surfaces are equivalent spellings (referential transparency); `$` in DOMAIN rows is a teaching placeholder only — substitute literals or bindings before execute.

**Continuation:** `label.<relation>` from surface/relation rows or row-preserving projections; aggregate/render/derive labels are not row anchors.

**Federated sessions:** when the same wire entity name appears in multiple catalog blocks (e.g. `Issue` on github and linear), use the **`e#` from the teaching row for that catalog** — not the bare entity name alone. Each `e#` is tied to `(catalog, entity)`; `p#` are per exposure wave.

**Filtering rows:** `e1{…}` filters at fetch; `binding.filter{…}` or `binding.filter(…)` filters materialized rows (same predicate grammar). Not `rows{…}` on a label.

**`group_by`:** `group_by(key, count=count)`; bare `group_by(key)` sugar for `count=count`. Multi-key: `group_by(k1, k2, n=count)`.

**Derived columns:** use `label => template` (Minijinja on `rows`), not `.derive(…)`.
