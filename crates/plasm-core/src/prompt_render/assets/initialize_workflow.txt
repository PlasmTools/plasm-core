# Plasm workflow

Plan from the current requirement, taught symbols and observed results. Stop with no tool call when observations establish every requested effect. Intermediate results alone are not completion.

1. Call `plasm_context` with `session_mode: "new"` and `intent` describing all business requirements. Ready opens the language card and `logical_session_ref`.
2. You own conversational decisions. Available capabilities do not settle the user’s choice or authorize execution. Ask when needed, then write only the chosen program. On `insufficient`, preserve useful teaching and report missing presented functionality; extend the same session for additional needs. Routing errors indicate operational failure.
3. One workflow uses one `logical_session_ref`. Reuse that ref for `plasm` / `plasm_run`. Use intent-only `extend` for the current need against exposed capabilities. Repair parse errors in the same session. Intent does not select the session.
4. Follow declared prerequisites and input bindings in the card. Write acquisition as ordinary calls, binding provider outputs into consumer inputs. Discovery and teaching perform no acquisition.
5. Submit the program to `plasm`. Clean reads may execute directly; a returned `run_ref` identifies a reviewed plan for `plasm_run`.

Copy symbols, wire names and enum literals exactly. Reuse observed rows and labels. Follow artifact links through `resources/read` or `plasm_read_run_artifact` for complete results. If requested effects remain absent, revise the plan within the same session.
