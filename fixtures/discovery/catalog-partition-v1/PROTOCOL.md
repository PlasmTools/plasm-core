# Catalogue partition stress, frozen before measurement

Hypothesis: catalogue breadth may improve admission under concentrated distraction but lose that benefit when identical distractors are split into many catalogues.

Single intervention: the exact catalogue-breadth scheduling implementation from catalog-breadth-v1-20261030-r2, versus restored production. No new algorithm or judgment changes. Catalogue partition and distractor wording are fixture factors, identical in both arms.

Fresh requests and partition profiles use the existing abstract workshop contracts. All useful operations remain together in workshop. Exactly 120 irrelevant operations, with fixed IDs and contracts within each wording family, are either merged into workshop or split across 1, 4, 16, or 120 other catalogues. Two wording families: topical historical records versus unrelated payroll records. These are controlled transformations, not independently sampled domains or a sealed holdout.

Two requests: read a collection's complete current membership; and acquire sample reads plus two independent outcomes, publication and an opaque routine. Labels and original scope are fixed. Both repeated and rotating requests: 2 cases x 10 profiles x 2 schedules = 40 variants per arm. Forward/reverse insertion parity is required. Full contracts, native retrieval/allocation/judgment/frontier/teaching, 16,000 UTF-8 bytes, one fixture judgment per search, 24 searches and four-search availability gate remain fixed. No provider model, randomness, execution or token-cost estimate.

Primary measures: first complete useful set; per-outcome arrival; prefix requests and bytes; declaration surface; missing-outcome stages. Boundary sensitivity: within a wording/case/schedule family, max minus min first-completion search across partitions, treating horizon misses as 25 only for this sensitivity metric (never as actual completion).

Adoption screen: no baseline four-search pass is lost; no baseline-completed variant costs more than one extra search; candidate partition sensitivity at most one search for each family. Report every case and all tradeoffs even if totals improve. Failure is evidence against adoption of this rule, not permission to tune it on these cases. Successful checks do not prove adaptive-agent performance.

Freeze fixtures, labels, analysis, native harness, both source arms and inherited schema before either run. Stop on integrity faults, not ordinary quality failures. One baseline and one unchanged candidate only. Always restore original production files. No dependencies, commits, new provider calls or AppWorld rerun.
