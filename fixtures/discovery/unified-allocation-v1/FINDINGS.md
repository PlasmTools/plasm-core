# A1: rejected, baseline restored

All 58 frozen development variants were measured once with the candidate.
Every variant retained exactly its baseline first-completion search, prefix
logical-request count and prefix admitted bytes. The six trajectory failures
remain; all 32 breadth and eight ordinary controls still pass. No byte or search
budget changed. Seven PostgreSQL ownership/continuation proofs and the TypeScript
concurrent session-extension check passed. No provider or AppWorld calls ran.

The broader native matcher check passed 133 tests and failed two existing abstract
invariants: `connected_supplier_after_required_acquisition_keeps_edge_roles` and
`unavailable_receiver_is_unexplored_not_a_byte_failure`.

The candidate routes input-supplier nominations through complete-root variants,
but those variants do not reconstruct optional suppliers attached inside required
acquisition ancestry. Filtering those nominations therefore loses valid evidence.
It also fails to record acquisition-cycle deferral when an alternative set is empty.
These are implementation defects, not evidence that the corresponding contracts
should be weakened. No tests or labels were changed to accept them.

This arm fails the frozen recovery, byte-improvement and invariant gates.
The production allocator and native/TypeScript v13 policy were restored; full
baseline Rust source identity was verified against the preregistration lock.
The restored matcher passed all 135 active tests (eight intentionally ignored).
Candidate source and hashes remain here for inspection. No post-result candidate
repair, second arm, commit or deployment was performed.

Lower observed construction times are diagnostic only: historical run conditions
differ, and dropping valid path expansion invalidates a parity-based efficiency
claim. This result does not falsify every correct implementation of unified
allocation. It shows that A1 did not change the measured starvation trajectory
and did not preserve the whole supported search space.
