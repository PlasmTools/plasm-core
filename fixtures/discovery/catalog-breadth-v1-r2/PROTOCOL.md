# Catalogue breadth before depth: frozen operational experiment

Hypothesis: within an existing exploration/connected-consumer priority tier,
interleaving catalogues prevents a large catalogue from monopolizing root admission
without disturbing the ordering of ordinary single-catalogue requests.

Trace basis: in the frozen repeated collection and independent-outcome trajectories
at 1,000 distractors, searches 2–4 admit 10–11 journal questions per packet while
cabinet_read or publish remains rank 1,005 and budget-deferred. Retaining all admitted
targets changes none of the 58 completion/search counts. This motivates admission
coverage, not a classifier change. Exact descriptions are not used by this candidate.

Single factor: root scheduling. Start with the existing lexical order and connected
consumer nominations. For each (visit count, connected-consumer flag, catalogue),
assign ordinal 0,1,2,... in existing order. Stable-sort by (visit count, disconnected
flag, ordinal). Within a tier, the highest-ranked first candidate from each catalogue
precedes second candidates. Stable ties preserve original relevance order. No
candidate is removed; visits and connectivity still dominate. Single-catalogue
order is unchanged. No entity quota, semantic grouping, task names, role boosts,
changed paths, changed allocation loop or new judgment instruction.

Catalogue boundaries are scheduling hints, not equivalence classes or guarantees
of usefulness. A catalogue can itself contain diverse tasks, and sharding a catalogue
can change its share. This arm does not promise to solve within-catalogue starvation.
It is a diagnostic development candidate and will be restored after measurement
even if promising; no silent production adoption or durable-state migration.

Fixed: current v13 production semantics except root scheduling and a distinct
experimental native policy identity; self-contained requests, full contracts,
monotonic exposure, fixture judgment/uncertainty retention, required acquisition,
optional alternative eligibility, existing frontier visits, one fixture request and
16,000 UTF-8 bytes per search, 24 searches. No provider, embeddings, dependencies,
effects, agent evaluation or AppWorld rerun. No task-specific catalogue edits.

Freeze protocol, baseline source copies, candidate source hashes and all existing
fixture locks before tests. Run the entire existing 58-variant matrix: v4 18, v5 32,
ordinary eight, including reverse-insertion parity. Compare to the contemporaneous

Also require every active native matcher invariant, plus fresh abstract checks for

This is a predeclared development tradeoff, not a revision of earlier experiments'
rejection criteria. A green signal is not a holdout or full-agent success claim.
