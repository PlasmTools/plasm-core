# Discovery trajectory v4: frozen development gradient

Hypothesis: the native selector and teaching pipeline exposes complete scoped paths within four searches even when near-topic bookkeeping operations compete across services. The baseline may fail: failures are the intended development gradient, never relabelled or excluded.

This is a model-free mechanical regression suite, not an agent evaluation, model-quality measurement, holdout or execution-success score. Three structural cases, growth 0/100/1000, repeated and rotating self-contained requests, forward/reverse insertion order. All are development data; the recorded production tasks are not loaded. The labels and requests are inaccessible to ranking/allocation except for the current request itself. Fixture labels are used only at the judgment seam and for scoring. No new instructions, catalogue changes or ranking fixes ship with this suite.

Freeze cases, schema, growth recipe and protocol before the first native measurement. Each run separately records source hashes and refuses overwriting results or source drift. No provider calls, new embeddings, dependencies or AppWorld execution.

## Construction and ground truth

The workshop schema is authored independently as a small abstract laboratory. The journal catalogue contains only copies of the historical `record` action, with unique opaque identifiers and identical contracts. Counts control catalogue growth, not classifier evidence. The workshop itself retains one record distractor. Primitive names carry no meaning: annotations define value domains. Nullary reads are explicitly receiverless, so no invented acquisition prerequisite is needed.

All capabilities omitted from a case's labels are unrelated to that case. The useful labels have direct authored purposes: sample_read supplies prepare, prepare supplies fire; cabinet_read embeds the complete member set, stamp changes those members, specimen_read is a valid optional read; publish is independent; routine is deliberately opaque and retained as uncertain. No journal operation changes resources. The collection outcome requires both the capability set AND the native exposed `Cabinet.specimens` relation. Merely returning stamp is insufficient.

## Run and score

Run all 24 searches, including after first completion, with one logical fixture judgment and at most 16,000 UTF-8 bytes per search. Main metrics use the prefix through first complete exposure, or all 24 on failure; post-completion work is separate. No retry is needed for fixture responses. Production root, frontier and packet policies remain unchanged.

The fixed requests are cycled verbatim or repeated verbatim. They are NOT adaptive agent-generated queries; comparing the two isolates sensitivity to self-contained paraphrases without a full agent run. This cannot reproduce every agent choice. No gold capability names are injected into requests by the harness.

Report per outcome first complete search, whole path first completion, missing-outcome area under the 24-search curve, no-gain searches before completion, repeated rejected judgments, selected cross-service negatives, full packet bytes, declaration bytes and indexing/selection time. Record lexical rank, root-frontier position, packet admission/defer reason, fixture decision, and actual taught relation visibility each turn. `ranking_unvisited` means absent from the root order, not a proven semantic model failure. A useful target may be nominated through a connected route; report raw receipts rather than overclaiming causality.

Quality gate: each outcome and required relation complete by search four, opaque targets retained, no unrelated exposure. Integrity gates: byte/request limits, exact target contracts, authorization, monotonic exposure and insertion-order parity. Quality failure produces a nonzero `quality` command, separately from native harness success. No baseline quality failures are marked xfail or converted to passing assertions.

Deliberate rejection diagnostic: use one predeclared service_effect/0 trajectory with the `fire` judgment forced unrelated. This is excluded from quality totals and must be reported as judgment rejection. It tests stage attribution; it is not a real model result.

Before any design change, retain the baseline unchanged. Improvements must reduce search-to-complete and missing-outcome area without losing independent outcomes or opaque uncertainty. If baseline passes all rows, state that this abstraction did not reproduce starvation and do not claim coverage of the recorded defect. Freeze a new version to explore the missing interaction; never edit these cases after scores.

Remaining boundaries: no host PostgreSQL persistence, semantic vector retrieval, program synthesis, execution, terminal submission or provider accuracy. Those need separate tests; a green result here does not establish full-agent viability.
