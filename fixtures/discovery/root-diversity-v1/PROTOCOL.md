# Root breadth: one-factor development experiment

Before candidate selection is measured, freeze this protocol and the counter-control cases. Keep trajectory-v4 inputs and its original baseline unchanged. This is development evidence, not a holdout, full-agent evaluation or provider-quality result.

Hypothesis: bounded packets should sample distinct catalogue-qualified resources before spending additional root slots on the same resource. Otherwise redundant operation families can consume the entire frontier while another requested outcome remains unjudged. This can affect ordinary broad APIs as well as replicated stress distractors.

Candidate: within each existing completed-visit count and connected-consumer priority tier, stably interleave roots by authored `(catalogue, owning entity)`. Preserve lexical order within a resource and the order of first appearance across resources. The only new state is a local per-resource ordinal in root ordering. No new classifier, learned heuristic, query rewrite, semantic name matching, hard exclusion, dependency, or budget change. Typed path expansion remains unchanged and can include several operations on one resource.

Counter-risk: useful same-resource operations could be displaced by unrelated resources. The frozen counter-controls cover same-resource read/action composition, a known-input direct action, an ordinary descriptive read, and two independent operations. They use the existing abstract schema with zero replicated distractors. They are development controls, not independently authored domains. Both repeat and paraphrase-cycle schedules are tested, and insertion reversal must preserve results.

Baseline and candidate use the same native selector/teaching harness and fixture judgments; 24-search diagnostic horizon, four-search gate, one logical judgment per search, 16,000-byte packet. Live classifier behavior, database admission and execution remain unmeasured. No AppWorld run or provider call.

Success: recover some or all trajectory-v4 four-search failures, no previously passing trajectory becomes failing, no increase in first-completion searches or prefix request count on zero-growth trajectories or counter-controls, and no violation of authorization/contracts/monotonicity/opaque retention. Report EVERY row, including any increased bytes. Do not choose a second candidate or adjust fixture labels within this experiment. If the tradeoff fails, retain the original production behavior and report it.

Policy identity must change before adoption because selection affects durable discovery reuse. Candidate receipts and manifests identify the new ordering. Adoption is contingent on frozen results plus focused existing native regression checks.
