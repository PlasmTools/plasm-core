# Progress v3: frozen development gradient

This is a domain-neutral development regression suite, not a holdout. It adds
coverage; fixed-v1 and starvation-v2.1 fixtures and labels remain unchanged.
Known failure mechanisms motivate it; no vendor/task names, programs or answers
enter production teaching. No provider or AppWorld calls, no executed effects.

Hypothesis: capability retention is insufficient unless relationships are usable
across exposure waves, and bounded calls must make measurable session progress.
One baseline only: unchanged native selector, packet renderer and exposure engine.
Budgets remain one logical request and 16,000 UTF-8 bytes per search. Fixture
responses consume no provider tokens; transport retries are outside this suite.

Freeze cases, labels, generation and this protocol before the first native run.
Use forward/reverse capability insertion; compare semantic trajectories exactly.
Twelve searches per scripted case, with observations at 1/2/4/8/12. This is a
measurement horizon, not a new production stopping rule. Carry visits and exposure
across needs; do not reset the frontier on a wording change. PostgreSQL ownership
and persistence remain covered by the existing six service concurrency tests.

Selection families: small complete paths; affordable large contracts; large
required evidence; irreducibly oversized target; identical repeated needs;
scripted paraphrases; accumulating long constraints; independent outcomes; opaque
uncertainty; denied capability; deliberate false-negative fixture judgment.
All authorized source/prepare/process capabilities contribute to processing.
Opaque is uncertain. Competitors are unrelated; denied targets are not selectable.
All labels are used only after the native selector admits questions.

Exposure diagnostics separately prescribe three acquisition schedules: endpoints
together, source then target, target then source. These are boundary controls,
not retrieval successes. Both endpoint reads must leave their authored embedded
relation callable; a target operation not selected must remain absent. Measure
the actual TeachingExposureSession relation symbol, not just retained IDs.

Metrics (do not collapse into a single score): earliest judgment, earliest retained
path, earliest usable relation, useful recall by horizon, repeated rejected
judgments, zero-gain searches, deferred reasons, root/frontier ranks, requests,
exact packet bytes, teaching capability/slot counts and local construction time.
For every target also measure its complete standalone packet at each turn: this
separates infeasible contract/history from competition within a feasible budget.
No truncation or omitted contracts. Capture exact packets and hashes.

Attribution: unauthorized, not indexed, ranking unvisited, allocation deferred,
judgment rejected, retained but untaught, usable. Stage is a measurement, not a
claim that changing only that stage suffices to solve an end-to-end task.

Hard gates: authorization, complete target contracts, budget bounds, additive
exposure and permutation parity. Quality failures must remain visible in reports;
a successful harness exit does not mean discovery passes. No threshold tuning
after measurement. An explicit quality-check command fails on unmet feasible path
or relation expectations while excluding the frozen impossible/denied/rejection
controls from positive coverage. These controls still verify attribution.

Use this as a gradient: change one mechanism, preserve all frozen versions, report
every recovery and regression, reject integrity violations, and prefer lower
first-usable search/work at equal coverage. A newly sealed structurally independent
acceptance set is still required for claims beyond development regression.
